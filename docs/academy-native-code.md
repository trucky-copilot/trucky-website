# ACADEMY dentro de Stripe Checkout

Cambio sobre la PR29: se elimina el campo Academia de la landing. Checkout usa `allow_promotion_codes:true`, SIN descuentos preaplicados, solo para plan29, modo live y ofertas habilitadas. El texto/etiqueta del campo y del error de código incorrecto lo controla Stripe y su localización, no se personaliza desde esta web.

Una cuenta Google tiene un Stripe Customer estable (clave Redis hasheada). Se crea un código privado ACADEMY por ese cliente, mismo cupón100% once existente, `max_redemptions:1`. No usar `first_time_transaction` porque excluiría clientes con una compra normal anterior; la regla de negocio es una vez por cuenta, no solo clientes nuevos. Stripe no permite que otra identidad use el código privado. También se reserva el intento atómicamente por cuenta entre organizaciones. Estados inciertos se conservan, sin TTL y sin borrado automático. El beneficio no se reinicia al cambiar correo, empresa o cupón.

Si ya se canjeó, o existe un intento de otra empresa pendiente, la cuenta aún puede abrir checkout normal SIN habilitar códigos. No se vuelve a emitir el beneficio. Un intento idéntico reutiliza cliente/código/payload. No se expira ni sustituye una sesión completada; las sesiones anteriores con descuentos preaplicados solo se reemplazan tras confirmar expiración en Stripe. Puede requerirse revisión conservadora de un recibo pendiente de la implementación anterior: no borrarlo a mano. No se concede segundo beneficio por una transición de implementación.

La metadata de la sesión indica elegibilidad, NO prueba uso del código. Solo el webhook firmado, tras consultar la factura de Stripe y ver el código privado + cupón correctos en la factura inicial de total0, enlaza el recibo a la suscripción. Si no se introdujo código, sincroniza la compra normal sin acreditar un beneficio. Renovaciones/cancelaciones sin descuento no se bloquean por ausencia de canje. Base44 exige la misma prueba y período inicial vigente, no acepta otras facturas0.
